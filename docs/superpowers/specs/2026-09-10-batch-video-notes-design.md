# BiliNote 批量视频笔记设计

日期：2026-09-10  
状态：已确认，待实施

## 1. 目标与范围

在现有本地部署版中增加“批量任务”功能。用户可以粘贴多行视频链接，也可以输入一个 B 站分 P 视频并选择需要的分集。系统按用户选定顺序严格逐条生成，每条视频单独产出一篇笔记。

首版范围：

- 多行链接支持当前本地版已有平台：Bilibili、YouTube、抖音、快手。
- B 站分 P 自动展开，支持全选、反选、清空和逐项移除。
- 每批最多 100 条。
- 单视频与批量任务共用一个执行槽，任何时刻最多生成一条笔记。
- 单条失败后记录原因并继续下一条。
- 桌面应用退出后保留进度，重新打开后由用户手动继续。
- 页面结构与用词参考 BiliNote 网页版的“新建批量任务”和“批量任务中心”。

首版不包含 B 站收藏夹、合集、UP 主投稿抓取，不包含自动后台常驻、并行生成、积分计费和多用户调度。

## 2. 已核实的项目现状

| 模块 | 当前情况 | 设计影响 |
| --- | --- | --- |
| 单条接口 | `POST /generate_note` 接收一个 `video_url` | 保持兼容，内部改为进入统一队列 |
| 任务执行器 | `task_serial_executor.py` 实际默认使用三个线程 | 统一为数据库队列的单执行槽 |
| 持久化 | 项目已有 SQLAlchemy 和默认 SQLite `bili_note.db` | 新增批次与子任务表，无需引入新数据库 |
| 任务历史 | 前端 Zustand/IndexedDB，后端 JSON 状态文件 | 新任务以 SQLite 为权威状态，旧历史继续兼容 |
| B 站分 P | 已有 `p` 参数解析和按页取得 `cid` 的底层能力 | 增加分 P 预览接口，并以 `BV + p` 区分任务 |
| 文件目录 | 截图等资源存在共用目录和按时间命名 | 每条任务使用独立目录，避免覆盖 |
| 完成状态 | 当前流程可能先写 SUCCESS，再保存最终 JSON | 调整为结果原子保存成功后再标记 SUCCESS |
| 前端轮询 | 网络请求异常会把任务标为失败 | 网络连接状态与任务状态分离 |

## 3. 产品交互

### 3.1 新建批量任务

入口放在首页侧栏“批量任务”，页面采用两个步骤：

1. **选择视频**
   - 多行文本框，每行一个链接。
   - 自动识别平台、规范化链接、标记重复和无效项。
   - B 站分 P 链接自动加载分集，显示封面、总标题、分 P 标题、时长和序号。
   - 列表提供全选、反选、清空和移除无效项。
   - 只有有效且已选条目进入下一步，最多 100 条。
2. **生成设置**
   - 复用现有模型、笔记风格、输出格式、原片链接、截图和视频理解设置。
   - 显示选中数量，提交按钮显示“开始生成 N 条笔记”。
   - 创建批次时保存设置快照，之后修改全局设置不影响该批次。

### 3.2 批量任务中心

侧栏增加“批量任务”。列表显示批次名称、来源、创建时间、总进度、成功数、失败数、等待数和中断数，并按“处理中、已完成、异常”汇总。

批次详情按输入顺序显示每条视频，状态包括：等待中、解析中、下载中、转写中、生成中、保存中、成功、失败、已中断、已取消。成功项可以直接打开原有笔记预览。

可用操作：

- 停止后续任务：当前正在执行的条目完成后，不再领取下一条。
- 继续生成：手动恢复等待项和已中断项。
- 重试失败项：只重新执行失败和已中断项，不处理成功项。
- 取消等待项：只取消尚未开始的条目。

批次结束只显示一次汇总提示，不为每条成功任务连续弹窗。进度显示真实阶段和完成数量，不估算虚假的剩余时间。

## 4. 执行、失败与恢复规则

- 按批次内的 `position` 严格逐条执行；全局同时只允许一个单视频或批量子任务运行。
- 单条失败后持久化失败阶段、用户可读原因和重试次数，然后继续下一条。
- 暂停或取消不强行终止当前下载、转写或模型请求，操作在当前条目结束后生效。
- 桌面应用真正退出会终止后端。下次启动时，遗留执行态任务改为 `INTERRUPTED`，等待项保持不变，批次进入可恢复状态。
- 手动继续前先检查最终结果；完整结果已落盘则修复为成功，否则复用有效的下载、字幕、转写和总结检查点，从缺失阶段继续。
- 缓存必须属于同一任务且配置签名匹配。模型总结缓存签名包含 `provider_id`、模型、风格和输出选项。
- 模型已返回但本地尚未保存时发生崩溃，恢复后可能再次调用模型。首版不承诺跨崩溃严格只调用一次。
- 前端轮询失败只显示“连接中断/正在重连”，不能把后台任务改成失败。
- 最终 JSON/Markdown 原子写入成功后，才能提交 SUCCESS；向量索引失败不改变笔记成功状态。
- 客户端生成 `request_id`，服务端对其建立唯一约束。同一次请求重发返回原批次，用户主动新建相同链接的另一批次仍然允许。

## 5. 数据与文件设计

沿用当前 SQLite/SQLAlchemy，新增：

### `note_batches`

- `id`：UUID 主键。
- `request_id`：客户端提交幂等键，唯一。
- `name`、`source_label`：列表展示信息。
- `status`：`PENDING | RUNNING | PAUSED | RECOVERABLE | COMPLETED | PARTIAL | CANCELLED`。
- `settings_json`：不含 API key 的共享参数快照。
- `created_at`、`updated_at`、`started_at`、`finished_at`。

### `note_jobs`

- `task_id`：UUID 主键，与现有笔记结果 ID 一致。
- `batch_id`：批次外键；单视频任务允许为空。
- `position`：批次内顺序。
- `original_url`、`normalized_url`、`platform`、`resource_key`。
- `title`、`cover_url`、`duration`：预览元数据。
- `status`、`stage`、`error_message`、`attempt`。
- `settings_json`、`checkpoint_signature`、`result_path`、时间戳。

批次和全部子任务在一个事务中创建，事务提交后唤醒调度器。API key 继续从现有 provider 配置读取，不复制进任务表。

每条任务使用 `data/tasks/<task_id>/`，下面划分 `media/`、`frames/`、`grids/` 和检查点文件。对前端可访问的截图复制到任务专属静态目录。B 站资源键必须包含 BV 号和 `p`，默认 `p=1`。

## 6. 后端结构与接口

新增一个随 FastAPI 生命周期启动和停止的 `NoteQueueService`。它通过数据库条件更新原子领取下一条可执行任务，单线程调用现有 `NoteGenerator`，并用阶段回调写入 `note_jobs`。首版只支持单后端实例；若检测到另一个活动调度器，应拒绝重复启动。

现有 `/generate_note` 保持请求与响应兼容，改为创建一个 `batch_id = NULL` 的队列任务。这样单视频不会绕过批量任务的严格串行限制。

接口采用现有 `/api` 路由前缀：

- `POST /batch/preview`：解析多行链接、展开 B 站分 P、规范化、去重并返回元数据；不创建任务。
- `POST /batch/submit`：保存批次和子任务，返回 `batch_id` 与任务 ID。
- `GET /batch`：分页查询批次中心。
- `GET /batch/{batch_id}`：返回批次计数与轻量子任务状态，不重复返回全部 Markdown。
- `POST /batch/{batch_id}/pause`：当前条目完成后暂停领取。
- `POST /batch/{batch_id}/resume`：手动继续。
- `POST /batch/{batch_id}/retry-failed`：将失败或中断项以新 attempt 重新置为等待。
- `POST /batch/{batch_id}/cancel-pending`：取消等待项。
- `GET /task_status/{task_id}`：保留旧接口，成功时继续返回原笔记结构。

领取、暂停、取消和重试都使用带当前状态与 attempt 条件的更新，防止一个任务被重复执行，也防止旧 attempt 的迟到状态覆盖新 attempt。

## 7. 前端结构

- 从 `NoteForm.tsx` 抽取可复用的生成设置组件，单视频与批量任务共用。
- 新增批次 API 类型与服务、批次状态 store、聚合轮询 hook。
- 新增 `BatchCreatePage`、视频选择列表、B 站分 P 选择器、`BatchListPage` 和 `BatchDetailPage`。
- 在现有首页布局侧栏加入“批量任务”入口，沿用现有 MarkdownViewer 打开成功笔记。
- 批次每三秒最多发送一个无重叠的详情请求；网络错误采用退避重试，进入终态后停止轮询。
- 修正前端 `FAILD` 拼写，统一后台实际状态，并按 `task_id` 幂等导入成功结果，避免刷新产生重复笔记版本。

## 8. 测试与验收

自动化测试覆盖：

- 多行链接规范化、无效项和同批去重。
- B 站 `BV + p` 标识、分 P 展开与选择顺序。
- 批次事务创建与 `request_id` 幂等。
- 单执行槽：混合提交单视频与批量任务时最大活动数为 1。
- 单项失败后继续、暂停边界、取消等待项和失败项重试。
- 启动恢复：执行态转为中断，成功项和等待项保持正确。
- attempt 条件更新阻止迟到写入。
- 原子结果保存后才写成功状态。
- 不同任务的媒体、截图和检查点互不覆盖。
- 轮询断网不会把任务标为失败，终态停止轮询。

交付前运行后端测试、前端构建与 lint，并执行至少三个条目的真实批次流程：包含一个 B 站分 P 视频、一个普通有效视频和一个故意失败的链接。验收时确认失败项不会阻塞后续任务，退出重启后可手动继续，成功笔记能在原预览页面打开。
